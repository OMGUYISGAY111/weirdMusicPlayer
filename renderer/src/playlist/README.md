# 播放列表（多列表）

分三层，各自不依赖对方的实现：

| 文件 | 职责 |
| --- | --- |
| `playlist.ts` | 无框架的**播放核心**：一个队列的播放、切歌、自动重试、播放模式。通过 `createPlaylist(resolveTrack)` 注入音频解析函数，`connect({ load, play, pause })` 接入播放器，`snapshot/subscribe` 对外提供状态 |
| `library.ts` | 多播放列表的**数据层**（纯函数）：列表记录、列表库、存档/导入导出格式、条目校验、同名处理、合并导入 |
| `persistence.ts` | 列表库的 localStorage 适配器（含 v1 单列表存档升级） |
| `hostAdapter.ts` | 搜索结果 → 统一曲目；按站点注册表解析视频音频 |
| `playbackAdapter.ts` | 连接播放控制器与播放核心（只有 `ended` 等事件，不碰列表结构） |

`stores/playlist.ts` 是唯一把三者拼起来的仓库：**一个播放核心 + 一份列表库**，并且把**选中列表**和**播放队列**分成两份状态：

- 选中列表（`activeId`）：界面上正在浏览 / 编辑的列表，切换它只改选中项，**不碰播放器**；
- 播放队列（`playerListId`）：播放核心里现在装着的那份列表，只有从列表里点「播放」（`playFrom`）或搜索页「立即播放」才会切换；
- 核心状态（条目 / 模式 / 当前曲目 / 历史）只写回 `playerListId` 对应的记录，所以浏览别的列表不会把 A 的歌写进 B；序列化文本没变就跳过写盘，暂停、缓冲这类变化不会反复写；
- 对播放中列表的增删改走核心（保证正在播的队列一致），对其它列表的增删改直接改记录；删除正在播放的列表会停掉播放，队列落到剩下的列表上。

`playFrom(listId, trackId?)` 是唯一会切换播放队列的入口：列表不是当前队列时，先把旧队列状态并回库、`replace()` 灌入目标列表（会停掉当前音频），再播放指定曲目。播放端始终只连接一个核心，不会重连、也不会留下后台播放或幽灵重试定时器。

## 列表管理

搜索页顶部是列表栏（`PlaylistBar.vue`）：点标签切换选中列表（**不影响正在播放的队列**；标签上的 `♪` 表示该列表是当前播放队列，选中态是另一种高亮），`＋ 新建列表` 新建并选中，当前选中标签上的 `✎` 重命名、`✕` 删除（两步确认；只剩一个列表时不能删）。每个标签后面是条目数，右侧是「导入 / 导出」。

搜索结果的「加入列表」会弹出目标列表菜单（`VideoSearch.vue`，teleport 到 body 的浮层）：选任意列表加入，或「＋ 新建列表并加入」（新列表不会抢走当前播放）。同一首再次加入只补全标题/作者/封面，不会重复。`立即播放` = 加进当前列表并播放。

## 存档与导入导出

- localStorage key：`music-player.playlists.v2`，格式 `{ version: 2, activeId, playlists: [...] }`。旧版单列表存档 `music-player.playlist.v1` 在首次启动时升级成「我的音乐」列表，旧键保留不销毁。
- 导出：整库写成 JSON 文件（`HostApi.ExportPlaylists` 弹系统保存框，UTF-8 无 BOM，文件名带时间戳）。
- 导入：`HostApi.ImportPlaylists` 读回文件文本，前端解析校验后**合并**进当前库（保留原列表）；新列表重新生成 id，同名自动追加「 2」。
- 兼容三种导入来源：本程序导出的整库、旧版单列表存档、只有 `items` 的裸列表对象；坏 JSON、空列表、未知格式明确报错，不影响当前列表。
- 校验规则与自动存档一致：坏条目、重复 id、运行期地址（`File` / `blob:` / `stream:`）会被丢弃；`currentId` 必须存在于条目列表，历史末尾必须对应当前项。

## 播放模式

底部「播放模式」可切换，也可调用 `playlist.setMode(mode)`：

| mode | 模式 | 自然播放结束 |
| --- | --- | --- |
| `sequential` | 顺序播放（默认） | 下一首，队尾停止 |
| `repeat-all` | 列表循环 | 下一首，队尾回到第一首 |
| `repeat-one` | 单曲循环 | 重播当前歌曲 |
| `shuffle` | 随机播放 | 随机选择另一首，仅一首时重播 |

模式按**列表**保存：每个列表记住自己的模式和当前曲目，切回来时是「已恢复列表，点击播放」。模式变更从下一次操作生效，不打断当前播放。单曲循环时手动上一首/下一首仍可切歌；随机模式的上一首返回最近播放记录（最多 100 条）。清空列表保留模式。

## 在别的页面加入歌曲

```ts
const playlist = usePlaylistStore()
const track = {
  id: 'my-library:123',
  title: '歌曲名',
  artist: '作者',
  source: { kind: 'audio', url: 'https://example.com/song.mp3' },
}
// 加进当前列表
const added = playlist.addTo(playlist.activeId, track)
// 或加进指定列表 / 新建列表（第二个参数传 null）
playlist.addTo('某个列表 id', track)
await playlist.play(track.id) // 只添加时不调用 play
```

ID 在列表内唯一，重复添加返回原 ID 并补全元信息。解析或播放失败时保留当前项，支持重试或手动切歌；移除播放中的曲目会播放相邻曲目，清空或取消解析会使未完成请求的结果失效（宿主下载任务可能仍会在后台完成）。

## 存储行为

应用使用当前站点的 localStorage，CEF 已配置磁盘缓存目录，数据随所选用户数据目录保留。开发服务器和正式版 origin 不同，分别保存；清除站点数据或更换用户数据目录会影响恢复。添加、移除、清空、增删改列表和当前曲目/模式变化立即写入；单纯播放状态变化不会重复写盘。存储被禁用、空间不足或存档损坏时不影响当前播放，搜索页显示存储错误。

视频保存原始页面链接，恢复后播放时重新解析。不保存播放器临时解析地址、错误、播放进度或自动播放状态。文件选择器得到的 `File` 以及 `blob:`、`stream:` 临时条目仍可在本次会话播放，但不会持久化；需要再次选择文件。直接音频来源支持持久化有效的 http(s)、app 和 file URL（地址指向的资源仍需存在）。

运行 `pnpm --filter renderer test` 验证核心、数据层、存档与异步切换行为，`pnpm build:web` 验证类型及构建。
